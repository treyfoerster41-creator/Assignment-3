### Revised approach

The first API implementation used SQLite's connection context manager directly. The unit tests passed, but Python reported unclosed-connection warnings because that context manager commits without closing. The connection helper was replaced with a managed wrapper that closes connections in `finally`; the backend suite then passed cleanly. See the curated [Part 2 implementation record](../prompts/002-assignment3-part2-implementation.md).

### Revised approach

The first draft of the 15-case API test supplied each fixture's expected answer from inside the test stub. It only checked persistence, not the app's recommendation logic. I changed the test to run the application's deterministic mock path. The first run then revealed that reusing one profile caused a vague S06 request to inherit the previous grounding recommendation. That is the intended history-personalization rule, not an independent interpretation of S06. I isolated each scenario in its own fictional profile, seeded S11's prior preference explicitly, and added a separate test that verifies a vague follow-up can use prior profile activity. The revised 15-case test passed.
